# Security and privacy boundaries

Phase 4 extends solo ownership with verified active room membership and private tournament entry. Membership removal revokes shared reads/signaling; authors can retain access to their own previously submitted text and drafts for export. Shared records never expose another member's profile/email, private draft or invitation secret. Hosts cannot convert themselves into independent judges. Reviewed results are immutable; only a role-authorized independent judge confirms them, with bilateral/global consent required for practice leaderboard credit. A judge is an authorized account, not an attested official. These safeguards do not prevent collusion or establish official competition integrity.

Invitation plaintext exists only at creation and manual joining, while SHA256 hashes live in an ungranted table. Room invites are single-account, event entrant invites bounded by capacity, all expiring/revocable. Token values stay out of URLs and persisted browser storage. WebRTC signaling is bounded and target/connection fenced, readable only through an authenticated live tick; expiry is enforced at read time and physically pruned by subsequent ticks. SDP/ICE and presence are excluded from export. TURN shared secrets remain API-only; ten-minute signed credentials are membership-authorized. Direct ICE can reveal peer IPs, disclosed at audio join. Floor/mute gating requires compliant clients; no centrally enforced media router is claimed.

Account deletion removes any containing room/tournament, including other members' shared transcript/results and derived ranking credits. The profile confirmation explains this effect. Local audio is own-microphone only, separately armed for each take, default off, bounded and never uploaded; it can be lost on forced exit. Other participants can record independently, and optional browser dictation may use vendor cloud processing.

- **Identity:** Supabase stores passwords and issues/rotates sessions. Next.js uses `getUser()` before rendering functional routes. FastAPI validates each bearer token with Supabase Auth and rejects unverified or anonymous identities. Session-specific verified JWT authentication time gates deletion; a different device's recent sign-in is insufficient.
- **Ownership:** every private table has ownership RLS and explicit SELECT grants. Direct client writes are revoked. RPCs serialize mutations with row locks, check ownership, validate turn/status/version invariants and constrain fields. Definer functions have fixed empty search paths and explicit execute grants. User-editable metadata never authorizes access.
- **Secrets:** cloud keys remain in authenticated React memory and request headers. The API does not persist, log, export or cache them. They are excluded from all account records. Clear credentials immediately removes the active key; page reload/sign-out/account switch clear it too. Authentication cookies contain Supabase session tokens, not provider keys.
- **Logging:** infrastructure must redact Authorization/X-AI-Key and disable request header/body capture. App errors map to safe messages without provider bodies or raw validation values. Do not enable HTTPX/httpcore debug logs or capture React state/inputs with session replay analytics.
- **Network:** production HTTPS and explicit CORS. Operator-controlled inference destinations, no arbitrary URL parameters, no followed provider redirects. Local endpoints refer to the API host. WebSockets require an exact allowlisted Origin and bounded first-frame authentication; provider keys never enter this transport. Identity is reverified periodically and owner access checked continuously.
- **Speech/audio:** microphone permission and explicit browser-speech consent precede capture. Browser vendors may process speech online; selecting local text inference does not change this. Optional MediaRecorder capture requires a separate per-take choice and is off by default. Files stay in bounded page memory (25 MB cap), with local preview/download/discard, no uploads or account retention. Blob URLs are revoked on discard/unmount. Unsaved-file warnings cannot protect against force-close/device loss. Recording consent is not a saved preference.
- **Streaming:** SSE previews are temporary. Only a complete bounded response is appended with the session version; provider interruption/cancellation cannot append partial output. Re-read the saved session after an interruption to resolve a possible commit/delivery race. Native speech processing is independent of provider text streaming.
- **Limits:** 64 KiB actual body limit, bounded fields, six turns per Quick Debate, 8,000 characters per turn/draft, bounded model response bytes, 75-second standard model timeout and 90-second streaming total deadline. WebSocket messages are small and rate bounded; configure the ASGI frame-size cap too. Database budgets are shared by all API workers. Internet-facing hosts should also configure edge IP throttling and Supabase's Auth rate/CAPTCHA controls; those external controls have not been provisioned here.
- **Untrusted content:** transcripts and model output render as React text, never raw HTML. Prompts separate untrusted transcript JSON from role policy. Models have no privileged tools or database/admin actions. Prompt injection defenses cannot guarantee perfect model compliance; output and factual assertions remain unverified.
- **Deletion:** requires explicit DELETE confirmation and recent session authentication. Global logout is attempted first, then server-only Auth deletion. Foreign-key cascades remove private data. Existing signed JWTs may remain cryptographically valid until expiry; API account checks and absent owned rows prevent access to deleted account data.
- **Exports:** return only the caller's records and exclude secrets. Exports page through database results. They are not a point-in-time snapshot when another device writes concurrently; pause edits for a consistent manual backup.
- **Testing:** mock Auth is isolated in `tests/fixtures/` and is never imported into app runtime. Mock AI is an explicit nonproduction adapter with visible labels. SQL isolation tests use PostgreSQL with simulated identities; live Supabase/Google/email/AI still require separate acceptance.
- **Analysis:** strict typed JSON is grounded to exact immutable turn quotes and speakers; duplicate/dangling graph nodes/links and stale snapshot versions are rejected. SQL repeats quote and score-bound checks before an atomic save. New private tables revoke direct writes and enforce ownership RLS/composite references. Repeated requests are idempotent. Model explanations/confidence remain uncertain even when an excerpt is exact.
- **Research:** only an explicitly consented OpenAI BYOK request may use native web search. Source links come from completed native-search citation metadata, with HTTPS/host checks; the application never fetches arbitrary source URLs. Missing citations cannot produce a verified/disputed label. This does not prove source relevance or truth. Current claim version/model/time/citations update together; previous assessment survives provider failure.
- **Progress:** only latest nonsimulated final evaluations contribute to score averages; saved model/rubric provenance remains visible. Achievements derive from account records. No audio is sent for judging, so delivery is unassessed. Learning records and exports are advisory, self-owned practice data, not attested official results.

Phase 1 self-owned transcripts are user-controlled practice data. Authenticated users can call their ownership-checked RPCs directly, including appending their own AI-labeled text. They are not authoritative competition records and cannot be used for official rankings. Later competition phases need privileged attestation, moderation and review boundaries.
